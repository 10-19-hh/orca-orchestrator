# Orca Studio — Art Direction & Visual Design Specification (Phase 2 초안)

상태: **방향 승인됨: Concept A (Cozy Developer Studio), 2026-11-28 사용자 승인.** 아래 규격이 Phase 3의 시각 기준이다.
Phase 3 시작 전에 남은 결정 사항은 §17에 있다(캐릭터 규격, 에셋 제작 주체, Node 툴체인).
산출물 목록: [`../index.html`](../index.html). 다시 만들기: `python3 design/orca-studio/tools/build.py`

## 이 문서의 산출물이 무엇인가 (정직한 구분)

- 이 폴더의 픽셀 이미지는 **코드로 그린 콘셉트 렌더**다. `tools/*.py`(표준 라이브러리만)가 도형·팔레트·명암 규칙으로 그렸다.
  - 픽셀 편집기로 그린 최종 에셋이 아니다. 이미지 생성 도구나 외부 에셋도 쓰지 않았다.
  - 목적은 방향, 비율, 밀도, 팔레트, 상태 표현을 **실제 픽셀 크기로 비교**하는 것이다.
  - 최종 품질은 픽셀 아티스트가 Aseprite 등에서 다시 그려야 나온다(§13).
- Hero 목업, 시트, 와이어프레임은 HTML이다. 장면 PNG를 정수 배율과 `image-rendering: pixelated`로 표시한다. 브라우저 100%에서 보는 것이 기준이다.
- 모든 장면은 `tests/fixtures/snapshot_v1/*.json`(모의 데이터)을 읽어 그렸다. 실제 관측 상태가 아니며, 모든 화면에 DEMO 표시가 있다.

**GUI에서 막아야 할 것 (규칙화):**
- 방 크기를 화면에 맞춰 늘리지 않는다. 고정 논리 해상도에 정수 배율만 쓴다.
- 구역마다 목적을 둔다. 빈 바닥은 동선 폭(최소 32px)만큼만 남긴다.
- 바닥은 장면에서 가장 낮은 대비를 갖는다.
- 시점은 하나만 쓴다(§6).
- 펫의 작업 동작은 예약해 두고 쓰지 않는다(§10).

## 2. Reference Study

**확인 범위:** 이번 작업에서 외부 웹 자료와 이미지를 **조회하지 않았다**. 아래 내용은 일반적으로 알려진 작품 특징에 대한 기억이며, 검증되지 않았다. 디자인 결정은 이 목록이 아니라 콘셉트 렌더로 비교해서 내렸다. 어떤 작품의 에셋이나 구도도 복제하지 않았다.

| 레퍼런스 | 가져올 것 | 가져오지 않을 것 | 참고 축 | 원칙으로 변환 |

## 4. Recommended Visual Direction

- **한 문장:** 저녁 무렵의 따뜻한 개인 개발실. 두 마스코트가 지내는 곳이고, 벽의 보드와 가운데 검증 장치가 프로젝트 상태를 조용히 말해 준다.
- **위계:** ① 상태 장치(보드·검증 장치·LINK) ② 마스코트 ③ 가구 ④ 벽과 바닥.
  - 바닥 대비는 가장 낮게: 판자 두 색의 명도 차 ≤ 3%, 줄눈 차 ≈ 12%.
- **감성 키워드:** Cozy, Calm, Crafted.
  - 귀여움은 실루엣과 반응에서 나오고, 과장된 이펙트에서 나오지 않는다.

## 6. Camera & Pixel Specification

| 항목 | 확정안 |
|---|---|
| 카메라 | 고정. 정면 위에서 비스듬히 내려다보는 3/4 (top-down oblique). 회전·원근·아이소메트릭 없음 |
| 투영 | 직교. 가구 = 윗면(깊이 d px) + 앞면(높이 h px). 윗면은 직사각형 |
| 논리 해상도 | **480×270** (16:9). 벽 y 0–84, 바닥 y 84–258, 앞 경계 258–270 |
| 타일 | 16×16 바닥 그리드. 벽 모듈 폭 16 (높이 84) |
| 월드 좌표 | 정수 픽셀, 원점 왼쪽 위. 바닥 위 위치 = (x, foot y) |
| 픽셀 크기 | 모든 요소가 같은 1 논리 픽셀. 크기만 다른 혼합 해상도 금지 |
| 캐릭터 | 캔버스 32×32, pivot (16, 31). Codex 실제 몸 24×29, Claude 28×20(팔 포함). 16은 표정이 안 읽혀서, 48은 방에서 너무 커서 탈락. 48은 Inspector 초상용 |
| 가구 비율 | 책상 84×26(윗면 14 + 앞면 12), 모니터 28×20, 의자 14×20, 검증 캐비닛 44×46(+ 램프 기둥), 보드 88×36, 소파 96×24 |
| 렌더 배율 | 정수만: `k = floor(min(availW/480, availH/270))`, k ≥ 1. 기준 1440×900에서 k = 2. 남는 공간은 바닥 `lip` 색으로 채움 |
| 샘플링 | nearest-neighbor. 캔버스 CSS `image-rendering: pixelated`. 서브픽셀 위치 금지(스프라이트 좌표 정수 반올림) |
| 화면 크기 변경 | k가 바뀔 때만 다시 배치. 480px보다 좁으면 축소하지 않고 선택 대상이나 요청 장치를 중심으로 자른다(crop) |
| 깊이 정렬 | 바닥 오브젝트·펫: pivot y 오름차순, 같으면 x. 벽 부착물은 항상 뒤. 그림자는 해당 스프라이트 바로 아래 |
| 레이어 | 0 창 밖 → 1 벽과 벽 부착물 → 2 바닥과 바닥 데칼(러그·빛 자국) → 3 y정렬 오브젝트·펫 → 4 조명 오버레이 → 5 장면 표시(말풍선·선택 고리) → 6 앱 UI(DOM) |

**필수 시각 규칙 (검증 항목):**
- 한 픽셀 밀도만 쓴다.
- 가구와 캐릭터 시점을 통일한다. 캐릭터 정면도 위에서 약간 내려다본 3/4다.
- 광원은 왼쪽 위 하나다. 그림자는 오른쪽 아래 3px, 접지 그림자는 타원.
- 디더링은 금지하고, 그라데이션 대신 2–4단 띠를 쓴다.
- 외곽선은 형태 색의 어두운 색조로 그린다(Codex `#35548f`, Claude `#82331f`, 목재 `#4f3322`). 순수 검정은 쓰지 않는다.
- 실루엣만으로 구분되어야 한다. 구름 머리 대 납작한 몸, 책상 대 캐비닛 대 소파.

  - 가속·감속은 각 2프레임(0.25s)이다.
  - 방향 전환은 정지 후 좌우 반전으로 한다.
  - 정지하면 1프레임 안정 자세를 둔다.
  - 그림자는 발과 함께 움직이고 점프 중에는 1px 작아진다.
  - 선택 반응: 1px 뛰기 1회 + 고리 표시.
  - 길찾기는 직선 + 가구 회피 지점(웨이포인트 3–5개)이다. 복잡한 길찾기는 하지 않는다.
- **우선순위:** end_unknown > failed > review > approved > passed > ready > idle.
  - 연결 끊김은 이 순서와 별개로 겹쳐서 표시한다.

## 11. Application UI Design — [`../ui-wireframes/index.html`](../ui-wireframes/index.html)

- **레이아웃:** A(장면 + 접히는 오른쪽 Inspector)를 채택한다.
  - B는 Review Queue를 펼친 상태로만 차용한다.
  - C(패널 전환)는 상태를 놓치기 쉬워 채택하지 않는다.
- **영역:**
  - Top Bar: 워크스페이스, DEMO, Runtime, 바인딩, Run, 전송 차단
  - Workspace
  - Task Board: 검증 기록 기준
  - Review Queue
  - Inspector
  - Status Bar: snapshot 출처, 마지막 조회, 움직임, 배율, 문서에 없는 정보
- **Activity Timeline:** 이번 단계에서는 두지 않는다. 이벤트 저장소가 없기 때문이다. 나중에는 `flow.status.last`와 `recovery.tasks[].attempt`만 "최근 기록"으로 보여 준다.
- **타이포:**
  - 시스템 산세리프 13px 기본, 제목 17px / 600
  - 모노는 ID, 명령, 상태 기호에만 쓴다
  - 픽셀 폰트(3×5)는 장면 안 라벨(`PASS`, `T-1`, `ON`)에만 쓴다
- **스타일:**
  - 테두리 1px `#3a3531`, 모서리 4px
  - 카드 남용 금지(목록은 줄 구분), 그라데이션 없음
  - 비활성 정보는 `#a2988b`
- **인터랙션:**
  - Hover는 이름 툴팁(마스코트·장치·구역)이다.
  - 클릭이나 Tab·Enter는 선택이다. Inspector를 열고 고리를 표시한다.
  - Esc는 선택 해제다. `+`/`−`는 정수 배율, `M`은 움직임(보통·줄이기·정지)이다.
  - 요청을 클릭하면 근거 Inspector가 열린다.
- **읽기 전용 경계:**
  - 실행·승인·재시도·전송 버튼은 **만들지 않는다**.
  - 필요한 명령은 점선 상자 안 모노 텍스트로만 보여 준다("이 앱은 실행하지 않는다").
  - 향후 명령 UI는 별도 영역(빨간 계열 경계 + 확인 단계)으로 둔다. Phase 7 이전에는 없다.
- **좁은 화면(≤ 900px):** 장면 ×1, 상태 한 줄, Review Queue, 접힌 Task Board 순서로 세로 배치한다.
- **Mini Mode:** 300×80. 장면 일부 + 상태 한 줄 + 요청 수. 애니메이션은 기본 정지.

## 13. Asset Production Pipeline

- **도구 (이번 단계에서는 사용하지 않음, 제안):**
  - Aseprite(유료, 태그·슬라이스·CLI 내보내기). 무료 대안은 LibreSprite·Piskel이다.
  - 원본 `.aseprite`를 저장소 `art-src/`에 둔다. 용량이 커지면 Git LFS를 검토한다.
- **내보내기:** `aseprite -b in.aseprite --sheet out.png --data out.json --format json-array --list-tags --sheet-pack`
  - 이 JSON은 PixiJS Spritesheet 형식으로 바로 쓰거나 변환 스크립트를 거친다.
  - 아틀라스는 시트별로 2048² 이하다.
- **명명:** `{category}_{name}[_{variant}].png`. category는 `mascot`, `station`, `board`, `device`, `furniture`, `prop`, `tile`, `light`, `fx`이다.
  - 애니메이션은 파일이 아니라 태그로 구분한다(`idle`, `blink`, `walk_side`, `react_*`, `happy`, `rest`). 예약 태그는 `work_*`.
- **규격:**
  - 마스코트: 32×32 프레임, pivot (16, 31), 투명 배경.
  - 가구: 바닥선 pivot.
  - 벽 부착물: 왼쪽 위 pivot.
  - 조명: 별도 PNG, add 합성.
- **팔레트:** 콘셉트별 `.hex` / `.gpl`. 새 색은 팔레트에 먼저 추가한다.
- **레이어:** 원본에서 `shadow` / `body` / `face` / `fx` 레이어를 나눈다. 그림자는 별도 스프라이트로 내보낸다.
- **메타데이터 예시:**
  - [`asset-manifest.example.json`](../asset-specification/asset-manifest.example.json)
  - [`scene-layout.example.json`](../asset-specification/scene-layout.example.json)
  - [`animation.example.json`](../asset-specification/animation.example.json)
- **향후 GUI 에셋 폴더:** `gui/assets/{sprites,tiles,lights,ui}` + `manifest.json`. 원본은 `art-src/`.
- **이미지 생성 도구:** 쓰지 않았다. 앞으로 쓰더라도 콘셉트 탐색용으로만 쓴다. 게임용 시트는 사람이 픽셀 단위로 정리해야 한다(팔레트·pivot·프레임 일관성). 외부 에셋은 라이선스와 출처를 `references/`에 기록하고, 불명확한 것은 최종 에셋에 넣지 않는다.

## 14. 디자인 원칙을 코드로 재현하는 법 (구현자 체크리스트)

1. 방 캔버스는 480×270 고정, 정수 배율 k, nearest.
2. 모든 스프라이트 좌표는 정수, pivot 기준.
3. 그리기 순서: 레이어 0–5 순서를 지키고, 레이어 3은 pivot y로 정렬한다.
4. 상태 → 장면 매핑은 순수 함수 하나로 만든다. `tools/build.py: scene_state()`를 TS로 옮기고 같은 fixture로 테스트한다.
5. 상태 표시는 색 + 기호 + 글자를 함께 쓰고, 정지 화면에서도 읽혀야 한다.

## 17. Remaining Limitations & Decisions

- **품질 한계:** 이 시안은 코드로 그린 콘셉트 렌더다.
  - 가구와 소품은 단순 도형 위주이고, 손으로 그린 픽셀 아트의 질감·디테일(목재결, 천 주름, 손때)이 없다.
  - 최종 품질을 보장하지 않는다.
- **조회하지 않은 레퍼런스:** §2는 기억에 의존했다. 필요하면 실제 레퍼런스 보드를 만들 것을 권한다.
- **애니메이션:** 프레임 시안(호흡·걷기·깜빡임)만 있고, 움직이는 프로토타입은 없다. 게임 필(가감속·반응 타이밍)은 Phase 3에서 확인한다.
- **폰트:** UI는 시스템 폰트를 쓴다. 웹폰트를 쓸지는 결정이 필요하다.
